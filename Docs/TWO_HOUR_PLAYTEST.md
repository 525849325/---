# 120 分钟体验验收记录

此记录用于真人平衡与主观体验调优；MVP 的机械 120 分钟时轴已有真实 Player soak 证据，但自动化不能代签“是否好玩”的主观结论。

## 运行准备

1. 启动 `Build/Windows/ImmortalLoot.exe`，选择离线演示或先启动 Development 后端再选择服务器登录。
2. 从首次进入战斗开始连续体验 120 分钟；允许正常查看页面、穿戴、分解、突破、领取任务与挂机。
3. Development Player 每 5 分钟自动写入 `immortal-loot-playtest.jsonl`。Windows 默认位于 `%USERPROFILE%\AppData\LocalLow\ImmortalLoot Studio\太初拾遗录\`（以 `Application.persistentDataPath` 为准）。
4. 结束后将采样文件复制到 `Docs/Evidence/`，并在下表填写实际时间与观察，不得预填 PASS。

## 检查点

| 实际分钟 | 必查体验 | 观察与问题 | 结论 |
|---:|---|---|---|
| 0–5 | 首战、首件装备、首次升级、弱引导是否清晰 | 待填写 | 待测 |
| 5–15 | 词条理解、Boss、第一种 Build 方向 | 待填写 | 待测 |
| 15–30 | 境界突破、渡劫、首个随机灵根 | 待填写 | 待测 |
| 30–60 | 功法选择、更高品质装备、分解循环 | 待填写 | 待测 |
| 60–90 | 三套 Build 差异、排行榜、任务/邮件/活动 | 待填写 | 待测 |
| 90–120 | 境界礼包入口、长期目标、付费点是否自然 | 待填写 | 待测 |

## 全程质量记录

- 是否每 3–5 分钟出现可感知成长：待测
- 是否存在超过 5 分钟无决策/无反馈的空窗：待测
- 是否出现卡关、死循环、重复发奖或存档异常：待测
- 最低/平均 FPS 与峰值内存（引用采样行）：待测
- 最想继续追求的装备或 Build：待填写
- 最困惑或最想关闭游戏的时刻：待填写
- 最终结论（PASS / NEEDS_TUNING / FAIL）：待测
